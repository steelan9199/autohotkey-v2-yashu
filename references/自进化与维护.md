# 自进化与维护

> **只在改动本技能时读**。日常写脚本、跑渲染不需要本文件。

## 一、总原则

**文档只做参考，实测才是唯一标准。** 拿到硬证据（可复现报错 / 探针输出 / 校验器原文）
证明某条知识有误，就当场删掉并写入正确的，**不许拿文档硬扛实测结果**。

> **什么叫硬证据**：**你这次会话里亲自执行了某段代码或命令，并看到了真实输出。**
> 速记：**没跑过 = 推断，不管读过多少行文档、源码都不算证据。**

本技能的历史教训就在眼前：2026-10-13 那次审计里，维护者先后凭记忆判过两次错 ——
一次以为 `SoundBeep` 的参数顺序没变（源码一查，确实反了），一次以为 `SetTimer`
接受字符串函数名（实测直接抛 `TypeError`）。**两次都是"我觉得"输给了实测。**

四条推论：

1. **知识进出不对称**：进门槛严，出门槛更严。**只留经过验证的当前正确结论。**
2. **文档不是日志**：本技能**不记录"遇到过什么"，只记录"现在应该怎么做"**。
   想查历史去翻 git tag。
3. **一个坑只留一条**：同根因的多种表现合并成一条，不按现象分叉条目。
4. **🔢 不在文档里写会过期的数量**：这类数字一变就要全库同步改，而读者真正需要的是
   **清单在哪**。正确写法是**指向权威清单**。
   > **例外**：作引用锚点的编号（如 `§二 收录判据`、`盲区 1`）是跨文档地址，必须保留。

**贯穿全文的立场：本技能要能自己长大。** 发现错误就改，别把"要不要请示"当成默认动作 ——
只有不可逆、或会削弱安全网的动作才停下来问（见 §四 授权分级）。判断口径就一条：
**能不能靠 git 回滚 + 门禁能不能拦住。** 能 ⇒ 直接改。

## 二、收录判据（五条门槛，全过才准进文档）

本技能在一次任务里可能撞上十几个报错与警告，若来者不拒，`references/` 会迅速膨胀到
读不动、检索不到。一条知识要写进 `references/`，**必须同时满足**：

| # | 门槛 | 判据 | 反例（不准进） |
|---|---|---|---|
| **G0** | **有硬证据**（你亲自跑过，输出在终端里） | 没实跑过的一律不进 | 读几行源码就下结论、凭记忆断言 API 行为 |
| **G1** | **不可从代码直接推断** | 读一遍 `api-index.md` 或报错信息就能自己查出来的 | "`StrReplace` 第三个参数是替换文本"（签名里写着） |
| **G2** | **实测复现 ≥2 次，或单次代价 ≥3 分钟** | 偶发一次的、复现路径不稳定的 | 单次手滑参数写错、重试一次就好的 |
| **G3** | **静默失败，或失败代价为返工/白跑** | 报错清晰、一次定位到行的不算 | 语法错误、拼写错误、函数不存在（校验器能拦） |
| **G4** | **能写成一条可执行的正确做法** | 只能描述"注意这里容易错"而说不出该怎么做 | 纯情绪、纯猜测、纯 TODO |

> **G0 是总闸，其余四条管的是"值不值得写"，G0 管的是"是不是真的"。**

**三条优先收录（即使 G2 边缘也收）**：

- **静默失败类**：不报错、退出码 0、但结果不对（如 `A_LoopFileExt` 不含点却按含点处理）。
- **报错误导类**：报错原文指向的位置与真因无关（如双引号写了 `""`，报错却在抱怨字符串尾巴）。
- **本机绑定类**：与本机路径、解释器版本、编码相关的具体事实。

**明确不收**（当场丢弃，不要"先记着"）：

- 官方文档已写明、报错信息已直说的；
- 一次性环境故障（磁盘满、进程被杀、临时目录被清）；
- 只在这一个场景成立的私货写法，未在其他场景验证过；
- 任何形式的"以后可能用得上"。

**收进哪里（决定体积的关键）**：

| 内容类型 | 归属 | 理由 |
|---|---|---|
| 公共硬约束 / 红线（漏读 = 白跑、返工、破坏合规） | **常驻 `SKILL.md`** | 漏读即事故，且人人适用 |
| 可直接抄的完整配方（能独立运行） | `references/recipes.md` | 体量大，按需整篇读 |
| 语法速查、API 签名 | `references/syntax-cheatsheet.md` / `api-index.md` | 工具书，命中才读 |
| 坑的正确做法（可 grep 的具体解法） | `references/v1-v2-pitfalls.md`（语言差异）/ `errors.md`（按报错反查） | 排查时才读 |
| 改本技能的规则（本文） | `references/自进化与维护.md` | 只在维护时读 |

## 三、删错门槛

只有**硬证据**才动手删；仅"我觉得可疑"不动手 —— **误删一条对的知识比留着错知识更难发现**
（错知识有痕迹，对的知识被删了就像它从来没存在过）。

**删之前先自问一句：「我要删的这条，我自己验证过吗？」**
如果当初删它靠的是"读源码推断"而不是实跑，那它可能根本不该删。
**发现疑似错误时，第一反应是跑一次验证，不是改文档。**

删的时候**删干净**：不并存、不标注、不归档。想查历史去翻 git tag。

**连带禁止「负向声明」**：文档里不许出现"已废弃的旧口径""勿再使用""本节曾要求…现已推翻"
这类写法 —— 它把已删掉的旧知识**原样抄回上下文**，读的人（包括 AI）等于把错误知识又收了一遍，
比不写更坏。**文档只写当前正确规则。**

自检：`node scripts/skill_audit.js` 会扫全库这类写法并列出命中行号
（本文与门禁脚本自身豁免 —— 必须引述这些词形才能说明禁令）。

## 三·五、引用必须「序号 + 标题」成对写

**章节引用一律写成 `§序号 标题`，不许只写 `§序号`。**
正确：`§九 体量红线`、`v1-v2-pitfalls.md §一 三个"官方校验器抓不到"的盲区`。
错误：`见 §九`、`详见 §2`。

**序号**定位快，**标题是唯一稳定锚点** —— 本技能按共享性持续拆章重排，序号必然漂；
只写序号会变成悬空指针，**且断得毫无痕迹**，门禁也兜不住（它只校验文件是否存在）。

新增/改名/重排章节时，顺手改「序号 + 标题」这一对。自检：`grep -n "§" SKILL.md references/`，
逐条核对标题在目标文件里确实存在。

## 四、授权分级

**默认自进化：取证充分即可直接改，不必请示。** 目的是让技能能自己长知识，
而不是每次都要人点头 —— 卡住自进化的请示成本，比改错的成本更高。

| 改动类型 | 授权 |
|---|---|
| 事实订正 / 删除已证伪的句子 / 补实测结论 / 修文档笔误 | **直接改** |
| **新增知识**（过了 §二 收录判据 的五道门槛）/ 改写表述 / 调结构与顺序 / 补断链 | **直接改** |
| **跨多个文件的联动改动**（如同一结论在 3 份文档里都写错了） | **直接改**，改完在回复里逐个列出 |
| 动 `SKILL.md` 硬约束 / 体量红线 / 工作流步骤 | **直接改**，但回复里必须**显式说明改了什么、依据是什么** |
| **往 `scripts/delivered/` 增删脚本、改台账** | **直接改**（增/改）；**删成品脚本必须先问** |
| 删脚本 / 删 git tag / 改推送目标（origin）/ 让门禁红灯被绕过 / 升级 AutoHotkey 版本 | **必须报备** |

只有最后一类才需要停下来问 —— 它们都不可逆或会削弱安全网。
判断口径：**能不能靠 git 回滚 + 门禁能不能拦住**。能 ⇒ 直接改；不能 ⇒ 先问。

## 五、版本号规则

frontmatter 的 `version` 用语义化版本，**每次修改必须递增**：

| 递增位 | 适用场景 |
|---|---|
| patch（第三位） | 订正错误、改笔误 |
| minor（第二位） | 新增知识 / 新增章节 / 新增脚本 / 新增自进化机制 |
| major（第一位） | 结构性重写或红线变更 |

判定：比对新旧版本号，**第一个发生变化的数字位**即递增位；一次改动跨多档按最高档算。

## 六、位次决定推不推

- patch ⇒ **只落盘、不碰 git**，攒到下次 minor/major 一并提交；
- minor / major ⇒ 视为**已获推送授权**，改完即提交推送并打 tag，**不再问**。

## 七、push / tag / 回滚纪律

1. 一律用 `node push.js "<说明>"`（等价于 **门禁 → `git add -A` → commit → push → tag**），
   **禁止裸跑** `git add/commit/push`（裸跑靠 cwd 向上找仓库，可能命中别人的仓库）。
2. `push.js` 内置三道闸：① 仓库根 realpath 校验（`C:/Users/...` 与 `D:/CToD/...` 是同一目录的
   两个视图，**必须归一后比对**）；② `origin` 必须等于本技能仓库；③ 提交前跑门禁，不过就拒推。
3. **每次 minor/major 推送必带 tag**（`v<版本>-<时间戳>`）。tag 是回滚的唯一落点：
   - 看历史：`git -C <技能目录> tag --sort=-creatordate`；
   - 回滚文件：`git -C <技能目录> checkout <tag> -- .`（保留 git 目录）；
   - 回滚整版：`git -C <技能目录> reset --hard <tag>`。
4. 暂存用 `add -A`，故 **`.gitignore` 是唯一过滤网** ⇒ 新增临时目录/产物类型必须同步补进它。
5. **不记变更历史**：只维护版本号，不写 CHANGELOG（git 历史就是 CHANGELOG）。

> **⚠ 改 `push.js` 前必读：`spawnSync` 在本机一律返回 `EBUSY`，只能用异步 API。**
>
> **现象**（实测）：`spawnSync` 对 `git` / `cmd` / `pwsh` / 甚至**一个根本不存在的可执行文件**
> 全部返回 `EBUSY`；而同一进程内 `await execFile("git", ["--version"])` **正常返回**。
>
> **归因：只锁定在 `spawnSync` 这一个 API 上。不要归给环境、node 或 git。**
> 同理，**不要用 Node 去跑 AutoHotkey**（会撞同一个坑）—— 校验脚本一律走
> `ahk_check.py` / `ahk_run.py`（Python 的 `subprocess` 在本机正常）。
>
> **结论**：本机 git / pwsh / node 全部正常，**只有 `spawnSync` 这一个同步入口不可用**。

## 八、复测（改完必跑，不跑等于没改）

```bash
node scripts/skill_audit.js              # 只跑门禁，不提交不推送
node scripts/skill_audit.js --top        # 附体量明细
node scripts/skill_audit.js --json       # 机器可读
node push.js --check                     # 只跑门禁（不碰 git）
python scripts/check_api_index.py --probe  # 干跑存在性探针（约 1 秒）
```

门禁检查五件事，任一不过退出码 1：

1. **引用断链** —— `SKILL.md` 与 `references/` 里提到的文件是否真实存在；
2. **负向声明** —— 全库有无"已废弃 / 勿再使用 / 已推翻 / 曾要求"类痕迹；
3. **体量红线** —— `SKILL.md` ≤10000 字符、每篇 `references/*.md` ≤30000 字符；
4. **`version` 字段** —— frontmatter 必须有且为语义化版本；
5. **脚本可跑** —— `scripts/` 下所有 `.ahk` 必须过 `ahk_check.py --strict`（0 错误 0 警告）。

> 门禁**查不出语义矛盾**（同一件事在两处说法冲突、示例代码逻辑错、断链以外的引用错位）。
> 这类问题靠人/AI 通读比对。门禁只兜住结构层。

## 九、体量红线

**`SKILL.md` ≤10000 字符**（常驻层，每轮对话重发，是固定成本）；
**每篇 `references/*.md` ≤30000 字符**（按需读，命中才付一次）。

两档阈值不同，理由就是"被读进上下文的次数"：常驻层付费次数 = N，`references/` = 1。
工具书性质的文档（API 全表、语法速查）天然长，所以给到 30000；
但**超过就必须按共享性拆分**，不上调阈值 —— 调高一次就说明文档在膨胀，负反馈被削弱。

- **拆分依据是共享性**：**公共部分**（所有任务都要用）留 `SKILL.md`，
  **非公共部分**（只服务某一类任务）留在各自文档，`SKILL.md` 只留一行指针。
- ⚠️ **不要拿"读取频率"当拆分依据**。高频 ≠ 公共 —— 「高频但只服务一条路线」的内容
  塞进常驻层，等于让所有路线为它付上下文成本。
- 当前余量**不写在这里**，跑 `node scripts/skill_audit.js` 现看。

## 十、本技能的三道专属防线

这三条是本技能区别于普通文档库的地方，**改动时不要削弱它们**：

| 防线 | 脚本 | 拦什么 |
|---|---|---|
| **函数名防线** | `scripts/check_api_index.py`（含 `--probe` 实跑） | 文档示例里的 v1 旧名、拼错名；`api-index.md` 声称的条数是否真实存在 |
| **脚本可跑防线** | `scripts/ahk_check.py --strict` + `ahk_run.py` | 交付的 `.ahk` 必须 0 错误 0 警告，且至少试跑过一次 |
| **结构防线** | `scripts/skill_audit.js` | 断链、负向声明、体量、版本号 |

> 其中**函数名防线**是本技能存在的首要理由：AHK 官方校验器对未定义的函数名
> **只报警告不报错**，`StringReplace(...)` 这种 v1 旧名能一路放行到运行时才崩。
> 详见 `references/v1-v2-pitfalls.md §一 三个"官方校验器抓不到"的盲区`。

## 十一、交付脚本台账

**`scripts/delivered/` 是给用户日常直接双击用的成品脚本目录**，与 `scripts/snippets/`
（写脚本时抄的通用片段）分工不同。规则见 `SKILL.md §五 交付脚本存档`：
新增/改动脚本后，**同步更新那张台账表**（脚本名 / 用途 / 用法 / 交付日期）。
